## Story

**As a** recruiter or audio engineer, **I want** to understand the player contract, transcription workflow, browser logic, and safety boundary, **so that** I can evaluate DrumAI beyond its interactive control surface.

## Acceptance Criteria

1. The current player remains the first experience and all controls remain compatible.
2. The page explains the public input/output contract, seven-stage conceptual pipeline, immutable pattern model, Web Audio scheduler, export format, decisions, tests, and limitations.
3. Public code snippets are real; private transcription implementation is represented only by clearly labeled pseudocode.
4. Unsupported timing/performance claims are removed.
5. README and standard actions expose demo, engineering case, source, and local run paths.
6. Unit, desktop/mobile Playwright, keyboard, audio gesture, reduced-motion, no-network, secret, and PII gates pass.
